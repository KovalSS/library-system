# Посібник користувача (User Guide)

## Бібліотечна інформаційна система

Цей документ містить опис користувацьких сценаріїв та інструкції щодо роботи з Бібліотечною інформаційною системою для всіх категорій користувачів: **Читача**, **Бібліотекаря**, **Адміністратора** та **Головного адміністратора**.

---

## 1. Ролі користувачів та модель доступу (RBAC)

| Категорія | Роль у системі | Основні обов'язки та можливості |
|---|---|---|
| **Читач** | `reader` | Пошук у каталозі, бронювання книг, перегляд власного формуляра видач, штрафів, сповіщень та персональних рекомендацій. |
| **Бібліотекар** | `librarian` | Обслуговування читачів у бібліотеці: ведення каталогу видань, інвентаризація примірників, оформлення видачі та повернення, прийом оплати штрафів. |
| **Адміністратор** | `admin` | Керування обліковими записами бібліотекарів, довідником літературних жанрів, перегляд аудит-логу дій та звітів. |
| **Головний адміністратор** | `chief_admin` | Створення та деактивація адміністраторів системи, повний аудит. Єдиний системний акаунт, що створюється при першому старті. |

## 2. Сценарій 1: Реєстрація, активація та вхід читача

### 2.1 Самостійна онлайн-реєстрація
Читач самостійно заповнює реєстраційну форму на сайті бібліотеки.
* **Запит:** `POST /readers`
```json
{
  "fullName": "Олена Коваленко",
  "email": "olena@example.ua",
  "phone": "+380501234567",
  "birthDate": "2000-05-14",
  "password": "SecurePassword123"
}
```
* **Результат:** Створюється акаунт у стані `pending_confirmation`.
* **Лист із токеном:** Система генерує одноразовий токен активації та надсилає лист (у середовищі розробки записується у файл `var/mail/outbox.jsonl`).

### 2.2 Підтвердження email
Читач переходить за посиланням із листа або надсилає отриманий токен:
* **Запит:** `POST /email-confirmations`
```json
{
  "token": "dGhpcy1pcy1hLXRva2Vu..."
}
```
* **Результат:** Акаунт читача стає активним (`active: true`), статус змінюється на `active`.

### 2.3 Вхід у систему (Отримання токена доступу)
* **Запит:** `POST /auth/login`
```json
{
  "email": "olena@example.ua",
  "password": "SecurePassword123"
}
```
* **Відповідь `200 OK`:**
```json
{
  "accessToken": "a8f3b2c9d1e...",
  "tokenType": "Bearer",
  "expiresIn": 3600,
  "userId": "6f0c1c52-4f43-4f6e-9a55-0c6a3d2c1a01",
  "role": "reader"
}
```
> [!NOTE]
> Токен доступу передається у всіх подальших запитах у заголовку:  
> `Authorization: Bearer <accessToken>`

> [!WARNING]
> Якщо ввести пароль невірно 5 разів поспіль, акаунт автоматично блокується на 15 хвилин (HTTP-відповідь `423 Locked`).

## 3. Сценарій 2: Пошук літератури в електронному каталозі

Читач або бібліотекар можуть здійснювати гнучкий пошук у фонді бібліотеки.
* **Запит:** `GET /editions?title=Кобзар&availableOnly=true&sort=popularity&order=desc`
* **Фільтри пошуку:**
  * `author` — пошук за автором книги (нечутливий до регістру, включно з кирилицею).
  * `title` — пошук за частиною назви.
  * `genreId` — фільтрація за конкретним жанром.
  * `year` — рік видання.
  * `availableOnly=true` — показати лише ті книги, які зараз фізично є на полицях.
  * `sort` — сортування за назвою (`title`), роком (`year`) або популярністю (`popularity` — за кількістю видач).

Приклад знайденої картки видання:
```json
{
  "id": "e3b0c442-98fc-1c14-9afb-4c2de940a001",
  "author": "Тарас Шевченко",
  "title": "Кобзар",
  "year": 2021,
  "isbn": "9789660100001",
  "genre": {
    "id": "g1",
    "name": "Поезія"
  },
  "price": 250.00,
  "totalCopies": 5,
  "availableCopies": 2,
  "loansCount": 42
}
```

## 4. Сценарій 3: Бронювання та черга очікування

Якщо читач бажає отримати видання, він може забронювати його дистанційно.
* **Запит читача:** `POST /reservations`
```json
{
  "editionId": "e3b0c442-98fc-1c14-9afb-4c2de940a001"
}
```

### Логіка обробки заявки:
1. **Якщо в бібліотеці є вільний екземпляр:**
   * Заявка отримує статус **`ready`**.
   * Для читача фіксується конкретний примірник (`copyId`).
   * Встановлюється термін отримання (`pickupDeadline`) — **рівно 2 доби**.
   * Читачу надходить внутрішнє сповіщення з датою дедлайну.
2. **Якщо всі примірники зараз на руках у інших читачів:**
   * Заявка отримує статус **`queued`**.
   * Читачу присвоюється позиція в черзі (`queuePosition: 1, 2, ...`).
   * Щойно один із примірників повертають до бібліотеки, черга автоматично зсувається: перший читач переходить у статус `ready` на 2 доби.
3. **Автоскасування:**
   * Якщо читач не забрав книгу протягом 2 діб, бронювання автоматично скасовується (`expired`), а примірник переходить наступному читачу в черзі.

## 5. Сценарій 4: Видача та повернення книги (робота бібліотекаря)

Усі операції з фізичними книгами здійснюються безпосередньо бібліотекарем.

### 5.1 Оформлення видачі (`POST /loans`)
Бібліотекар обирає читача та сканує інвентарний номер екземпляра.
```json
{
  "readerId": "6f0c1c52-4f43-4f6e-9a55-0c6a3d2c1a01",
  "copyId": "c1a0-copy-uuid"
}
```

> [!IMPORTANT]
> **Автоматичний контроль заборгованості (REQ-F-051):**  
> Якщо читач має хоча б одну неповернуту прострочену книгу або несплачений штраф за попередні видачі, система блокує оформлення видачі з помилкою `409 Conflict`:
> ```json
> {
>   "code": "reader_has_debt",
>   "message": "У читача є прострочена видача або несплачений штраф."
> }
> ```

**Правила розрахунку терміну користування:**
* Якщо на видання **є черга очікування**: термін становить **14 днів**, ставка можливого штрафу — **5%** від ціни на день.
* Якщо черги **немає**: термін становить **30 днів**, ставка штрафу — **1%** від ціни на день.

### 5.2 Повернення книги (`POST /loans/{id}/return`)
Коли читач повертає книгу:
* Бібліотекар надсилає запит повернення.
* Статус видачі змінюється на `returned`.
* Екземпляр повертається на полицю (`available`) або, якщо в системі є читачі в черзі, автоматично бронюється для наступного за чергою читача (`ready`).

## 6. Сценарій 5: Штрафи за прострочення та їх оплата

1. **Нарахування штрафу:**
   * Якщо книгу не повернуто вчасно, система автоматично рахує прострочення за кожен прострочений день:  
     $$\text{Штраф} = \min(\text{Ціна видання}, \text{Ціна} \times \text{Ставка \%} \times \text{Дні прострочення})$$
   * Штраф не може перевищувати 100% вартості книги. Коли штраф досягає вартості книги, видача отримує стан **`compensated`** (вартість книги повністю компенсована штрафом).
2. **Перегляд заборгованості читачем:**
   * `GET /readers/{id}/fines` — повертає перелік усіх штрафів та загальну суму боргу:
   ```json
   {
     "readerId": "6f0c1c52-4f43-4f6e-9a55-0c6a3d2c1a01",
     "currency": "UAH",
     "totalOutstanding": 50.00,
     "items": [
       {
         "loanId": "l1",
         "editionTitle": "Енеїда",
         "fineAmount": 50.00,
         "paidAmount": 0,
         "outstandingAmount": 50.00
       }
     ]
   }
   ```
3. **Реєстрація оплати бібліотекарем:**
   * Читач сплачує борг у бібліотеці (готівкою або банківською карткою).
   * Бібліотекар реєструє повне погашення заборгованості: `POST /readers/{id}/fine-payments`
   ```json
   {
     "method": "card"
   }
   ```
   * Після реєстрації оплати блокування на нові видачі з читача автоматично знімається.

## 7. Сценарій 6: Кабінет читача — сповіщення та рекомендації

### 7.1 Внутрішні сповіщення (`GET /readers/{id}/notifications`)
Читач отримує системні повідомлення:
* За 2 дні до закінчення терміну повернення книги (`due_soon`).
* У перший та кожен наступний день нарахування штрафу (`overdue_fine`).
* При появі замовленої книги з черги у стані готовності до отримання (`reservation_ready`).

### 7.2 Персональні рекомендації (`GET /readers/{id}/recommendations`)
* Система аналізує історію видач читача та пропонує книги тих самих авторів чи жанрів, які зараз є в наявності.
* **REQ-F-052 (Адендум 2):** Книги, які читач уже колись брав у бібліотеці, автоматично виключаються зі списку рекомендацій, щоб не пропонувати вже прочитане.

## 8. Сценарій 7: Адміністрування та аналітичні звіти

Співробітники бібліотеки мають доступ до звітності:

1. **Топ популярних видань (`GET /reports/top-editions`):**
   * Параметри: `from=2026-01-01&to=2026-10-31&limit=10`.
   * Показує найбільш запитувані книги бібліотеки.
2. **Звіт про заборгованість (`GET /reports/debtors`):**
   * Список усіх читачів, які мають неповернуті прострочені книги або непогашені штрафи, із контактними даними для зв'язку.
3. **Завантаженість бібліотеки (`GET /reports/library-load`):**
   * Кількість оформлених видач та прийнятих повернень за вказаний період.
4. **Експорт у CSV:**
   * Будь-який аналітичний звіт можна завантажити у форматі таблиці CSV, додавши HTTP-заголовок `Accept: text/csv`.
5. **Аудит-лог дій (`GET /audit-log-entries`):**
   * Адміністратори можуть переглядати історію операцій користувачів із фільтрацією за датою та виконавцем.
