# Довідник REST API Бібліотечної системи

Цей документ є повним технічним довідником реалізованого REST API (контракт `spec/openapi.yaml`, версія 1.0.0). Він описує всі 38 операцій API, їхні параметри, авторизаційні вимоги (RBAC), формати відповідей та зв'язок із вимогами SRS (`spec/srs.md`).

## Загальні конвенції взаємодії

* **Базовий URI:** `http://127.0.0.1:8000` (локально) або відносний `/` при роботі через зворотний проксі.
* **Інтерактивна документація (Swagger UI):** доступна за адресою `http://127.0.0.1:8000/docs`.
* **Формат обміну даними:** `application/json; charset=utf-8` (для аналітичних звітів підтримується `text/csv`).
* **Автентифікація:** передача Bearer токена в HTTP-заголовку `Authorization: Bearer <token>`.
* **Ідентифікатори:** валідні рядки UUID v4 (36 символів).
* **Часові мітки:** формат ISO 8601 UTC (наприклад, `2026-10-31T12:00:00Z`).
* **Грошові суми:** десяткові числа в гривнях (UAH), заокруглення до копійок.
* **Єдина модель помилки (`Error`):**
  ```json
  {
    "code": "reader_has_debt",
    "message": "У читача є прострочена видача або несплачений штраф.",
    "requestId": "req-9b87f2e1a4c0"
  }
  ```

## 1. Автентифікація та сесії

### `POST /auth/login`
**ID операції:** `login`  
**Короткий опис:** Вхід у систему  
**Вимоги SRS:** `REQ-F-009`, `REQ-F-010`, `REQ-F-012`, `REQ-F-013`, `REQ-F-014`, `REQ-F-016`, `REQ-F-048`, `REQ-NF-003`  
**Дозволені ролі (RBAC):** Публічний (без авторизації)  

> Після 5 поспіль невдалих спроб акаунт блокується на 15 хвилин —
відповідь `423` із заголовком `Retry-After`.
Деактивований акаунт і акаунт читача без підтвердженого email
отримують `403`.


#### Тіло запиту (`application/json`):
Схема: `LoginRequest`

#### Коди відповідей:
| Код | Опис | Схема відповіді |
|---|---|---|
| `200` | Автентифікація успішна. | `LoginResponse` |
| `400` | Запит не відповідає схемі (відсутні обов'язкові поля, неправильні типи чи формат). | `Error` |
| `401` | Невірний email чи пароль. | `Error` |
| `403` | Акаунт деактивовано або email ще не підтверджено. | `Error` |
| `423` | Акаунт заблоковано на 15 хвилин після 5 невдалих спроб входу. | `Error` |

---

### `POST /auth/password-reset-requests`
**ID операції:** `requestPasswordReset`  
**Короткий опис:** Запросити лист для скидання пароля  
**Вимоги SRS:** `REQ-F-047`  
**Дозволені ролі (RBAC):** Публічний (без авторизації)  

> Відповідь завжди `202`, незалежно від того, чи існує акаунт з такою
адресою, щоб не розкривати наявність облікових записів.


#### Тіло запиту (`application/json`):
Схема: `PasswordResetRequest`

#### Коди відповідей:
| Код | Опис | Схема відповіді |
|---|---|---|
| `202` | Запит прийнято; якщо акаунт існує, лист надіслано. | — |
| `400` | Запит не відповідає схемі (відсутні обов'язкові поля, неправильні типи чи формат). | `Error` |

---

### `POST /auth/password-resets`
**ID операції:** `resetPassword`  
**Короткий опис:** Встановити новий пароль за токеном із листа  
**Вимоги SRS:** `REQ-F-047`, `REQ-NF-003`  
**Дозволені ролі (RBAC):** Публічний (без авторизації)  

> Токен надходить у листі, створеному за `POST /auth/password-reset-requests`; недійсний чи прострочений токен — `400 invalid_token`.

#### Тіло запиту (`application/json`):
Схема: `PasswordReset`

#### Коди відповідей:
| Код | Опис | Схема відповіді |
|---|---|---|
| `204` | Пароль змінено. | — |
| `400` | Тіло некоректне або токен із листа недійсний чи прострочений. | `Error` |

## 2. Управління читачами та реєстрація

**ID операції:** `registerReader`  
**Короткий опис:** Самостійна реєстрація читача  
**Вимоги SRS:** `REQ-F-015`, `REQ-F-017`  
**Дозволені ролі (RBAC):** Публічний (без авторизації)  

> Створює акаунт читача у стані `pending_confirmation` і надсилає лист із
посиланням підтвердження. Повторна реєстрація на email, що вже
використовується підтвердженим акаунтом, — `409`.


#### Тіло запиту (`application/json`):
Схема: `ReaderRegistration`

#### Коди відповідей:
| Код | Опис | Схема відповіді |
|---|---|---|
| `201` | Акаунт створено, очікує підтвердження email. | `Reader` |
| `400` | Запит не відповідає схемі (відсутні обов'язкові поля, неправильні типи чи формат). | `Error` |
| `409` | Email уже використовується. | `Error` |

**ID операції:** `confirmReaderEmail`

**Вимоги SRS:** `REQ-F-016`

|---|---|---|
| `200` | Акаунт активовано. | `Reader` |
| `400` | Тіло некоректне або токен із листа недійсний чи прострочений. | `Error` |
