# API-GATE: рішення контрольної точки

**Що оцінюється:** контракт `spec/openapi.yaml` (OpenAPI 3.1, 38 операцій) за
затвердженою `spec/srs.md`, адендум `logs/api-addendum-1.md`, проєктні нотатки
`docs/api-design.md`, сценарії `tests/api/`. Серверної реалізації немає — вона
починається в лаб. №5.

## Обмеження та невирішене

* Mock повертає приклади й перевіряє форму запиту, але не виконує бізнес-логіку
  (ролі, стан даних, розрахунок штрафу). Коди 403/404/409/423 у сценаріях вибираються
  заголовком `Prefer: code=…`. Правильність правил перевірятимуть тести лаб. №5.
* Прогалини SRS B1–B5 (`logs/api-addendum-1.md`) не закриті; жодна не блокує
  контракт, але B1 (відмова у видачі боржнику) варто вирішити до тестів видачі.
* `spec/srs.md` усе ще містить REQ-F-022 без позначки про скасування (див.
  адендум, розд. C). Розбіжність некритична для контракту, але її слід усунути.
* Нові коди помилок, ролі та пагінація — технічні уточнення (адендум, розд. A);
  нової функціональності в контракті немає.
