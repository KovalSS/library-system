# Адендум до SRS: відмова у видачі читачу із заборгованістю (REQ-F-051)

**Статус:** запропоновано, очікує SPEC-ADDENDUM-GATE.
**Дата:** 31.10.2026. **Тікет:** LS-41 (Addendum).
**Базова специфікація:** `spec/srs.md` (затверджена на SPEC-GATE), `spec/openapi.yaml`
(затверджений на API-GATE).

## 1. Потреба

Затверджена SRS дозволяє видати книгу читачу, який не повернув іншу вчасно або не
сплатив штраф. Прогалину виявлено ще під час проєктування API
(`logs/api-addendum-1.md`, B1) і зафіксовано як свідоме очікування базової
реалізації на TEST-GATE-3 (T19: «видача боржнику дозволена»).

Наслідок для бібліотеки: читач може накопичувати невернуті книги й борги, а фонд —
зменшуватися. BDD-сценарій 8.1 SRS уже неявно спирається на протилежне правило:
його передумова — «читач не має прострочених видач чи несплачених штрафів».

## 2. Нова вимога

| ID | Опис | Пріоритет | Розділ SRS |
|---|---|---|---|
| **REQ-F-051** | Відмова в оформленні видачі читачу, який має заборгованість: хоча б одну прострочену неповернуту видачу або несплачений штраф. | High | 4.3 Видача та повернення |

**Визначення заборгованості** збігається з визначенням боржника у звіті REQ-F-040,
щоб у системі було одне поняття «боржник»:
* прострочена неповернута видача — видача в стані `active` або `compensated`, у якої
  минув термін повернення;
* несплачений штраф — сума нарахованих і не сплачених штрафів за всіма видачами > 0.

## 3. Критерії прийняття

| # | Критерій |
|---|---|
| AC-1 | Спроба видати книгу читачу з простроченою неповернутою видачею повертає відмову `409 reader_has_debt`; видачу не створено, екземпляр лишається доступним. |
| AC-2 | Те саме для читача, який повернув книгу із запізненням і не сплатив штраф. |
| AC-3 | Те саме для читача з видачею в стані «не повернуто, компенсовано повною вартістю», якщо штраф не сплачено. |
| AC-4 | Після сплати штрафу (REQ-F-030) і за відсутності прострочених неповернутих видач видача знову дозволена. |
| AC-5 | Читач із поточною, ще не простроченою видачею боргу не має — видача дозволена. |
| AC-6 | Відмова записується в системний журнал як WARNING із причиною (REQ-NF-005: помилки критичних операцій). |
| AC-7 | Заборгованість перевіряється раніше, ніж доступність екземпляра: причина відмови стосується читача й не залежить від обраного екземпляра. |

## 4. BDD-сценарій (новий розділ 8.6 SRS)

**Сценарій: Відмова у видачі читачу із несплаченим штрафом**

- **Given** читач «Іван Петренко» повернув книгу із запізненням і має несплачений штраф 45 грн
- **And** видання «Кобзар» має доступний екземпляр
- **When** бібліотекар оформлює видачу екземпляра видання «Кобзар» читачу «Іван Петренко»
- **Then** система відмовляє з поясненням «у читача є заборгованість»
- **And** екземпляр лишається в статусі «доступний»
- **When** бібліотекар реєструє оплату штрафу 45 грн
- **And** знову оформлює видачу
- **Then** видачу оформлено

## 6. Що свідомо не змінюється

* Бронювання боржником (REQ-F-023, 024) не забороняється: адендум стосується лише
  видачі. Якщо читач із боргом прийде по заброньований екземпляр, видачу буде
  відмовлено до сплати; бронювання скасується автоматично через 2 дні (REQ-F-025).
* Ліміту кількості одночасних видач не вводиться.
